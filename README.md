# Video Lab - 動画計測Webアプリ（v11）

## v11：FPSと倍率の双方向連動

「再生FPS変更・DL」タブでは、「出力再生FPS」と「再生速度（元動画に対する倍率）」を並べて表示します。選択方式のラジオボタンはありません。

- **出力FPSを変更** → 再生倍率が自動更新（倍率 = 出力FPS ÷ 元動画FPS）
- **再生倍率を変更** → 出力FPSが自動更新（出力FPS = 元動画FPS × 倍率）
- 例：120 FPSの動画で「0.5倍」なら60 FPS、「2倍」なら240 FPS。「30 FPS」を指定すれば「0.25倍」を表示。
- 動画の入力ファイルを変更した際は、元の記録FPS（1.0倍）へ両方の設定をリセットします。
- 既存の選択区間、エンコード方式、フレーム数・FPS検証、MP4保存処理に変更はありません。倍率指定でもフレームは間引かず、全フレームを保持して再生時間だけ変更します。


## v10：大容量動画の高速シーク・検証・処理段階表示

「再生FPS変更・DL」タブの途中区間書き出しに、次の機能を追加しました。

- **高速シーク**：`ffprobe` で動画のフレーム時刻（PTS）・キーフレームを索引化し、要求開始フレーム直前のキーフレーム付近から FFmpeg でデコードします。322,560フレームなど長い動画の後半を処理する場合、先頭からの全フレームデコードを避けられます。索引作成は圧縮パケットの情報を読む処理なので、フレーム画素のデコードは必要ありません。索引はファイルサイズ・更新日時でキャッシュします。
- **フレームの正確性**：パケット数が元動画のフレーム数と一致し、全フレームに一意のPTSがある場合のみ高速シークします。FFmpegの実際のデコード入力から切り出された **先頭と末尾のPTS** を索引のフレーム番号と照合し、出力フレーム数とFPSも検証します。**一致しなければ高速出力を破棄して、従来の先頭からの逐次デコードに戻ります。**
- **段階表示**：「索引を確認中」「キーフレームへ高速シーク中」「デコード中」「エンコード中」「MP4書き込み・確定中」「境界・フレーム数・FPS検証中」を表示します。出力フレームがまだない間も0%表示と経過時間を更新します。
- **ファイル保存中**：変換完了後「指定したPCのパスに保存」を押すと、4MiBごとにコピー進捗・経過時間を表示します。ファイルは既存パスへの上書きを禁止し、コピー失敗時は作成途中のファイルのみ削除します。

### 高速シークに必要な ffprobe

高速シークには **`ffprobe` コマンド** が必要です。FFmpegのフル配布版に含まれます。Windowsでは `ffprobe.exe` をPATHが通ったフォルダ、またはVideoLabが使用する `ffmpeg` 実行ファイルと同じフォルダに配置してください。インストール後はコマンドプロンプトで `ffprobe -version` が動くことを確認してください。

`imageio-ffmpeg` だけでは `ffprobe` が付属しない環境があります。その場合や、パケットPTSが欠落・重複している動画、メタデータが不整合の動画では **安全のため自動的に従来の先頭からの逐次デコード**に戻ります。画面にはその理由を表示します。

元動画は変更しません。映像の「FPS変更・区間指定」は表示時刻を書き換える処理であり、フレーム補間や間引きは行いません。再圧縮されたMP4の画素値は元動画と一致しないため、計測には元動画を使用してください。VFR・独自コーデックでは高速化が適用されない場合があります。


## v9: FPS変更の高速化・大容量MP4の保存

- 元動画がH.264で**全区間**をFPS変更する場合は、FFmpegのビットストリームフィルタでPTS/DTSを調整し、再圧縮なしの高速コピーを自動試行します。映像の圧縮データは変更しません。出力FPSまたはフレーム数が一致しなければ自動で再エンコードに切り替えます。
- AVI/MJPEGや指定区間の切り出しは、OpenCV→Pythonの1枚ずつのBGR転送を廃止し、FFmpegの \`trim\` → \`setpts\` → H.264エンコードを一つのプロセスで実行します。フレームの間引き・補間はしません。
- エンコード速度は「高速（ultrafast）」「標準（veryfast）」「容量優先（medium）」から選べます。高速ほど一般にファイル容量は大きくなります。
- 出力ファイルは一意のファイル名で一時保存するため、次の変換で直前のファイルを上書きしません。
- 出力後の「指定したPCのパスに保存」は **Streamlitを実行しているPC** の絶対パスにMP4を直接コピーします。既存ファイルの上書きは禁止です。遠隔サーバー上で起動した場合、閲覧中のPCへはコピーされません。
- ブラウザの「ダウンロード」ボタンは **128 MiB以下の出力** に限定しました。大容量動画を \`read_bytes()\` でブラウザ向けに全量読み込むメモリ負荷を避けます。
- **元動画は常に維持します。** 再エンコード時はH.264非可逆圧縮になるため、計測解析は引き続き元動画を使用してください。
- **固定フレームレート（CFR）動画向け** です。VFR／独自コーデック／長尺動画の後半部分については、メタデータや厳密なフレーム対応を実ファイルで検証してください。部分区間は誤ったシークを避けるため動画先頭から読み取るので、開始位置が後半だと時間がかかる場合があります。


動画を**その場でFPS変更・フレーム送り**し、画像計測・画像処理、再生FPS変更MP4の保存とオプティカルフロー解析も行える、ローカル実行向けStreamlitアプリです。
計測ロジックを `videolab/` に分割しており、後から機能を追加できます。

## 機能

1. **インタラクティブ再生**: ブラウザ内で動画を開き、表示再生FPSを任意に変更（基本的にファイルの再エンコード不要）。1枚／10枚送り、キーボード矢印キー、タイムライン、フレーム番号ジャンプ、先頭／末尾ジャンプができます。
2. **再生FPS変更・範囲指定（v6）**: 元動画内の任意の開始・終了位置を、**フレーム番号または秒数の範囲スライダー＋数値入力**から指定して書き出せます。範囲内の全フレームを残し、出力MP4の再生FPSを変更。**出力再生FPSのアプリ側2000 FPS上限を撤廃**しました。
3. **オプティカルフロー（v4）**: **初期状態は手動の点選択**。任意の開始フレームを表示し、画像をクリックして追跡点を追加。クリック位置をそのまま使う設定が初期値です。任意でクリック近傍からShi–Tomasi特徴点への自動補正をONにできます。元の「画面全体から自動検出」モードも切替可能。Lucas–Kanade法で追跡し、軌跡・ベクトル動画と点ID付きCSVを出力します。
4. **画像計測・画像処理**: 既知寸法の2点校正、距離・角度計測、α/β、二値化、簡易輪郭抽出、画像重ね合わせ、差分。後述のv3説明を参照。
5. **AVI互換MP4変換（v5）**: AVI等をブラウザ向けH.264 MP4へ変換する際に、**元動画のFPSをそのまま維持**します（120→120 FPS、800→800 FPS）。**全フレーム変換が初期値**で、必要な場合のみ先頭Nフレームを指定できます。元動画は変更せず、解析も元動画を使用します。
6. **動画形式**: MP4 / AVI / MOV / MKV / M4V入力（実際に読めるコーデックはOpenCV/FFmpegの環境に依存）。H.264 MP4出力。

### MP4の「互換形式変換」と「再生FPS変更」は別機能です

- **互換MP4変換（通常はこちら）**：動画の形式だけAVI等→MP4(H.264)に変え、フレームレートを**元の記録FPSのまま**維持。120 FPS / 600フレームの5秒動画なら、変換後も120 FPS / 600フレーム / 5秒です（固定FPS動画を想定）。再生速度はプレーヤーで一時的に変更できます。
- **再生FPS変更・DLタブ（明示的操作）**：ユーザーが意図的に異なる出力FPSを設定した場合のみ、再生時間を変更したMP4を書き出します。

互換変換はFFmpegで再エンコードするため、H.264コーデック、画素形式yuv420p、画質はCRF23に変わります。映像フレーム・画素値のバイナリ一致は**保証されません**。元AVIのメタデータタグはMP4に表現できるものを移行しますが、全タグの保持は保証されません。音声がある場合、最初の音声ストリームをAACに再エンコードします。奇数解像度は1画素のパディングを加える場合があります。

### v6：範囲指定・任意FPSでの書き出し

1. 動画を読み込んで「再生FPS変更・DL」タブを開きます。
2. 「出力再生FPS」に任意の正の値を入力します。初期値は元動画FPSで、**最大値はプログラム側では設定していません**。ただし、非常に高い値ではH.264エンコーダーや再生ソフトの制約で変換に失敗したり、正しく再生できない場合があります。
3. 「指定単位」を **フレーム番号** または **動画の秒数** から選びます。2つのつまみを動かす**範囲スライダー**と**開始・終了の数値入力**は同期します。単位を切り替えても選択範囲は維持されます。
4. 必要なら「開始・終了フレームの画像を確認」で元動画の端点画像を表示します。後半のフレームは読み取りに時間がかかる場合があります。
5. 「選択区間のFPSを変更してMP4を作成」をクリックし、結果を保存します。

フレーム番号は**0始まり・開始終了とも含む**方式です。例：開始240、終了479とすると240枚出力されます。秒数は**元動画の先頭基準・開始を含み終了を含まない**方式です。例えば120 FPSの動画で2.000〜4.000秒を選ぶと、240〜479フレームになります。出力FPSを30にすれば出力動画は8秒です。時間を指定した場合は、元動画のフレーム境界に丸められます。画面に実際の抽出フレーム番号・元の時間区間・出力予定フレーム数・出力予定秒数を表示します。

**重要：** この機能は**選んだ区間だけを書き出すトリミング＋再生FPSの変更**です。動画全体を残したまま中間の区間だけをスロー／高速再生する機能ではありません。区間外は出力されません。フレームの補間・間引きはせず、指定された範囲のフレームを順番に読み取ります。元AVIは変更しません。音声は書き出しません。

大容量出力では自動プレビューを省略しますが、MP4は保存できます。大きなファイルのダウンロード時にはStreamlit側のメモリ利用に注意してください。元動画内の後半を選ぶ場合、AVIの不正確なランダムシークを避けるため開始フレームまでは先頭から順次デコードし、処理時間が長くなる場合があります。なお、OpenCVによる元動画のFPS・総フレーム数はメタデータベースです。可変FPSの動画は秒数からフレームへの対応が正確でない場合があります。

### 再生FPS変更タブの例

例：元動画が **800 FPS、8,000フレーム** の場合

| 出力FPS | 出力フレーム数 | 出力の再生時間 |
| --- | ---: | ---: |
| 800 | 8,000 | 約10秒 |
| 30 | 8,000 | 約266.67秒（スローモーション） |
| 100 | 8,000 | 約80秒 |

**単に間引いて動画の長さを維持する『フレームレート変換』とは違います**。v6でも**選択した区間内の全フレーム保持方式**です。
フレームを補間する機能もありません。

## 起動手順（Windows 11・uv推奨）

1. Python 3.11以上と [`uv`](https://docs.astral.sh/uv/) をインストール。
2. ZIPを展開して、そのフォルダでPowerShellまたはコマンドプロンプトを開く。
3. 実行：

```powershell
uv sync
uv run streamlit run app.py
```

または `run.bat` をダブルクリックすると必要な環境を自動セットアップして起動します。

4. ブラウザで **http://localhost:8501** を開き、動画をアップロード（同じPC上のローカルWebアプリへ転送）して処理します。

初回のみ依存ライブラリのダウンロードが必要です。2回目以降は通常そのまま起動できます。

### uvを使わない場合

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -e .
streamlit run app.py
```

## 画面の使い方

- **その場で再生・コマ送り** タブ：「動画を開く」から動画を選択し、「元動画FPS」（動画の記録FPS）を確認。「表示再生FPS」を変えると再生速度が変わります。±1/±10フレームボタン、フレーム位置スライダー、フレーム番号入力、キー操作ができます。最初にページ上部からアップロードした16 MiB以下の動画は自動読み込みされます。大容量動画はプレーヤー内のファイル選択から直接開きます。
- **再生FPS変更・DL** タブ：意図的に再生時間を変えたい場合だけ使用します。目標FPS（上限設定なし）を指定し、フレーム番号または秒数で開始・終了を選び、MP4に保存します。**数値入力と範囲スライダーは連動**します。
- **オプティカルフロー解析** タブ：デフォルトの手動モードで開始フレームを決め、表示画像をクリックして追跡点を追加（複数可）。「クリック付近の特徴点へ自動補正」は初期状態OFF。必要ならONにして探索半径を指定。取り消し・一括削除も可能。追跡中の自動追加も初期状態OFF。
- **画面全体から自動検出**に切り替えると、従来のShi–Tomasi自動選択と追跡中の点補充を使えます。
- **AVIのブラウザ表示**：「その場で再生・コマ送り」タブ → 「AVI・独自コーデック向け」→ 先頭フレーム数（初期値0＝全フレーム）を必要なら設定 → 「互換MP4を作成してプレーヤーで開く」。**元動画のFPSを保持し、出力FPSの選択項目はありません**。元AVIは変更されません。
- **プレーヤーのキー操作**：`←/→` で±1フレーム、`Shift + ←/→` で±10フレーム、`Space` で再生/停止、`Home/End` で先頭/末尾。プレーヤーをクリックしてからキー操作します。数値入力欄にカーソルがあるときは矢印キー操作しません。
- **プレーヤー単独起動**：Python・Streamlitを起動しなくても `assets/frame_player.html` をEdge/Chrome等で開けば基本的な動画再生・コマ送りができます。この場合は元動画FPSを手動で指定してください。
- 出力ファイルはブラウザから保存可能。作業中の一時ファイルはOSの一時ディレクトリに保存されます。セッション終了後も一時ファイルが残る場合があるため、運用に応じて削除してください。
- ファイルの標準アップロード上限は `1GB` に設定。ファイルを処理するためPC側に十分な空き容量が必要です。

## CSV仕様

CSVは `utf-8-sig` で保存され、Excelでも日本語環境で読みやすい形式です。

| 列 | 意味 |
| --- | --- |
| `frame` | 0始まりの入力フレーム番号 |
| `time_s` | `frame / 動画メタデータFPS`。可変FPS動画では概算 |
| `point_id` | 検出時に採番した追跡点ID。再利用しない |
| `x_px`, `y_px` | 画素位置。左上(0,0)、右方向が+x、下方向が+y |
| `dx_px`, `dy_px` | 1フレーム間の変位。初回検出時は空欄 |
| `speed_px_s` | `sqrt(dx² + dy²) × 動画メタデータFPS` |
| `status` | 1: 検出・追跡中、0: 追跡喪失 |

**注意**：CSVの時間・速度は入力動画FPSから計算し、結果動画の再生FPS設定には影響されません。速度はpx/sです。実距離（mm/s等）にするには画素スケール校正が必要です。レンズの歪み、カメラと対象面の傾き、反射、ブレなどは未補正です。また、点の速度がそのまま設備の速度と一致するとは限りません。

## プレーヤーの再生FPSについて

例えば **800 FPS記録・8,000フレーム** の動画を開き、元動画FPSを800、表示再生FPSを30にすると、意図する再生時間は約267秒です。表示再生FPSを変更してもファイルは変わりません。

ブラウザがサポートする倍速範囲では動画の再生レートを変更し、極端なスロー／倍速では時間経過に合わせてフレーム位置を更新する方式を使います。高FPS・高圧縮・高解像度では処理落ちやフレーム飛びが発生し得ます。

フレーム送りはブラウザの動画時刻シークに基づく**近似値**です。GOPの影響、ブラウザの動画デコーダ、可変FPS（VFR）などにより、物理的に厳密な1枚送りは保証されません。**画像計測の座標・速度算出には従来どおりPython/OpenCVでフレームを読み取ります。**

### 動画の読み込み経路

- プレーヤー内のファイル選択：ブラウザで直接開くので大容量動画でもStreamlit側に転送不要。ただしフレームレート情報は自動取得できないため、元動画FPSを確認・入力してください。
- 画面上部のアップロード：Pythonで解析とMP4書き出しが可能になります。16MiB以下のファイルはプレーヤーへ自動埋め込みされます。容量を超えるファイルは、動画をプレーヤー内で再度選択してください。
- AVIや一部MOV/MKVのコーデックはブラウザがサポートせず再生できない場合があります。**その場で再生・コマ送り**タブの互換MP4プレビュー変換を利用してください。コーデックによってはFFmpegも読み取れません。
- 他のStreamlitウィジェット操作でアプリ全体が再実行されると、プレーヤー内で開いた動画の位置はリセットされる場合があります。

## 現在の制約

- **互換MP4変換のみ**、元動画に音声があれば最初の音声ストリームをAACとして出力します。再生FPS変更タブとオプティカルフロー結果動画は音声を含みません。
- 奇数幅・奇数高さの入力動画はH.264の互換性確保のため、右端・下端に最大1画素だけ黒帯を追加する場合があります。
- **フレーム保持による動画時間変更**のみ。元の再生時間のままフレームを間引く/補間する操作とは別です。
- **固定FPSの動画を想定**。可変FPS（VFR）、壊れた動画、メタデータが不正な動画では時刻・速度が正しくならない可能性があります。
- 解析は基本的にCPU。長時間・高解像度では処理時間と一時保存容量が増えます。
- コマ送りの厳密な1フレーム精度や、指定再生FPSでの滑らかな表示はブラウザやコーデックによって保証できません。
- 計測精度の保証はありません。前後追跡による誤追跡低減は行いますが、実使用前には検証が必要です。
- ローカル利用を想定。インターネット公開するときはユーザー認証と転送動画の扱いを別途設計してください。

## v3 追加：画像計測・簡易画像処理

VideoLabの **「画像計測・画像処理」タブ** を利用してください。動画をアップロードしていなくても使えます。PythonやStreamlitなしで試す場合は、`assets/image_lab.html` をChrome/Edgeで直接開きます。画像処理はブラウザ内部で完結し、ファイルを外部送信しません。

### 機能

- **校正**：定規に限定せず、寸法が既知の任意の対象（部品幅、ゲージ、基準マークなど）を2点クリック。基準寸法を数値入力し、mm / µm / cm / m / inch / 任意単位で校正。実寸係数を「単位/px」で表示。
- **別撮りの校正画像**：計測画像Aとは別に「校正用画像」を選択可能。基準画像と計測画像の撮影倍率・解像度・撮影面は同じである必要があります。Aを入れ替えると、誤適用防止のため校正をクリアします。
- **距離・角度**：画像A上で2点間距離、3点角度（2点目が頂点）をクリック計測。校正後の距離は任意単位で表示し、計測PNG・CSVを保存可能。角度は度。
- **α/β**：各RGBチャネルの `clip(alpha * I + beta, 0, 255)` を使い、コントラスト・明るさをプレビュー調整。初期値α=1.0、β=0。
- **グレースケール／二値化**：しきい値（0〜255）、白黒反転を切り替え。
- **輪郭表示**：二値化後の白領域を8連結成分でまとめ、境界画素を赤く表示。最小面積（px²）で領域除去。領域個数・総面積・最大面積を表示。OpenCVの `findContours` をそのまま使う精密モードではありません。
- **画像重ね合わせ**：2枚の画像A/Bを重畳して、Bの透過率を設定。手動の水平・垂直位置補正（px）あり。
- **画像差分**：位置を合わせたA/BのRGB画素差の平均絶対値を色で可視化。差分強調倍率を変更可能。領域外の差分は黒表示。実装上、**α/βは画像Aのみに適用**され、画像Bは原画像です。差がない箇所は暗く、差がある箇所が明るくなります。

### 操作手順

1. `計測画像 A` を読み込む。比較する場合のみ `比較画像 B`、別画像で校正する場合のみ `校正用画像` を追加。
2. 基準長さと単位を入力して「基準の2点をクリック」を押し、画面の2点をクリック。基準長さを変えたら再度2点を指定する。
3. 「2点間距離」または「3点角度」に切り替えて、計測画像Aで点を選ぶ。
4. 「表示方法」でα/β、二値化、輪郭、重ね合わせ、差分を試す。
5. `表示画像をPNG保存`、`計測値をCSV保存`。

### 各方式の違い

- **画像重ね合わせ**：AとBを半透明で表示し、位置ズレ・変化を目視で確認する手法。
- **差分表示**：同一座標の画素強度差を演算して可視化する手法。カメラブレや照明差も差分として現れます。
- **テンプレートマッチング**（**未実装**）：切り出した小さな画像パターンが、別画像のどの位置にあるかを探索する手法。特徴ある部品の位置検出や追跡、A/B位置合わせの補助に使えます。

### 計測上の注意

校正係数は、レンズ歪み、焦点距離・ズーム、撮影距離、画像解像度、被写体面、斜め撮影の影響を受けます。別の画像に同じ係数を使えるとは限りません。距離計測は画像上で選んだ2点間の距離です。特に斜めからの撮影では単一のmm/pxで正しい実寸にならない場合があり、射影変換やレンズ補正が必要です。輪郭ピクセル面積を実際の面積に換算する際も平面校正・歪みなどの検討が必要です。計測画面上のプレビュー操作は元画像データを変更しません。

**制約**：v3の画像処理タブは静止画像向けです。動画の任意フレームを直接このタブへ読み込む連携、テンプレートマッチング、自動位置合わせ、OpenCVによるサブピクセル精密輪郭抽出は未実装です。必要な静止画像は動画から画像として保存して読み込んでください。ブラウザでの処理のため、非常に高画素の画像は二値化・輪郭描画が重くなる場合があります。

### Pythonモジュール（将来の動画フレーム処理向け）

`videolab/image_processing.py` に以下のOpenCV画像処理関数も用意しています。表示用HTMLはブラウザ内JavaScriptで描画しますが、将来は同じ処理のPython版を動画各フレームへ適用する設計です。

- `alpha_beta(image, alpha, beta)`：8-bit BGR画像の飽和変換
- `binarize(image, threshold, inverted)`：グレースケール化＋二値化
- `contour_overlay(image, threshold, inverted, min_area_px)`：領域境界の重畳・ピクセル面積統計
- `overlay(a, b, opacity_b, dx, dy)`：ネイティブ画素スケールで重畳
- `difference(a, b, gain, dx, dy)`：画像差分の疑似カラー表示
- `units_per_pixel(known_length, p0, p1)`：任意の既知寸法から校正係数を算出

ブラウザ簡易輪郭抽出とPythonのOpenCV輪郭描画では境界の画素表現に差が出る場合があります。重要な寸法測定はPython版処理と既知寸法で確認してください。

## v4 追加：手動オプティカルフロー追跡点指定

### 機能と初期値

| 設定 | 初期値 | 説明 |
| --- | --- | --- |
| 追跡点の決め方 | **手動** | 開始フレームを開き、任意の場所をクリックして点を追加 |
| クリック付近の特徴点へ自動補正 | **OFF** | OFF: 指定座標をそのまま使用。ON: 半径内からShi–Tomasi特徴点を選ぶ |
| 追跡中に新しい点を自動追加 | **OFF** | OFF: 指定点だけを追跡、喪失しても勝手に別の場所を追加しない |
| 開始フレーム | 0 | 0始まりで任意のフレームを指定。変更すると登録点をクリア |
| 追跡点の取り消し | 対応 | 最後の1点を削除、または全部クリア |
| 全画面自動検出モード | 選択可能 | 従来の自動特徴点抽出＋定期的な再検出 |

### 使い方

1. 上部から動画を読み込み、「オプティカルフロー解析」タブを開きます。
2. 「手動で選択（デフォルト）」を確認し、必要なら「追跡を開始するフレーム」を指定します。
3. 右側で「クリック付近の特徴点へ自動補正」のON/OFFを決めます。初期状態OFFなら**座標は勝手に移動しません**。
4. 画像をクリックして追跡点を1点以上追加します。追加順にID 1, 2, 3...が付与され、画像と表に表示されます。点の取り消し・全削除も可能。
5. 「解析して動画・CSVを作成」で追跡し、結果を保存します。

初期追跡座標は**選択した元画像の画素座標（px）**で記録されます。表示画像を縮小していても元の解像度へ換算します。開始フレームが0以外の場合、CSVの `frame` と `time_s` は**元動画の先頭を基準**に保持し、出力動画は指定フレームから始まります。フレーム抽出は画面表示・解析ともに先頭からの連続デコードで行うため、時間はかかることがありますが、AVIのランダムシーク誤差を避けています。

クリック近傍からの自動選択は、指定点から設定半径内で `cv2.goodFeaturesToTrack` により角点を選ぶ操作です。適切な点が見つからない場合は登録せず、警告します。**自動補正ON/OFFの切替はその後に追加する点に適用され、既存の点は変更しません**。

### 計測上の留意点

- 手動で指定した座標でも、平坦な表面や反射部ではLucas–Kanade法の追跡が難しい場合があります。補正ONでの角点選択を試してください。
- 手動選択時の新規追加がOFFなら、点を見失った場合は `status=0` で終了し、別の点に置き換えません。ONなら追加される点は別IDです。
- 一度失った点を同一IDで追跡再開する機能、点ごとの信頼度評価、mm/s変換は未実装です。
- 近傍補正は追跡の成功を保証するものではありません。LK前後追跡誤差でフィルタを掛けていますが、実試験前に既知変位で精度確認してください。
- 依存ライブラリ `streamlit-image-coordinates` が新たに必要です。`uv run` 起動時にインストールされます。

### AVIの再生について

ブラウザが直接読み込めないコーデックでも、FFmpegがデコードできれば再生用MP4を別途作成できます。**v5から元動画のFPSをそのまま使用し、例えば120 FPS→120 FPSのMP4になります。** OpenCVで元FPSを読める固定FPS動画では、入力FPSからフレーム時刻を再設定してフレーム数・FPSを検証し、一致しなければ変換失敗として通知します。元FPSが取得できない動画はFFmpegが読み取ったPTSを使用します。可変FPS（VFR）動画は固定FPSとしての変換を行う場合があるため、計測用には元動画を使ってください。映像はH.264で再圧縮されます。対応不能な独自コーデックにはカメラメーカーのデコーダが必要になる場合があります。

`pytest -q` でv6のテスト39件成功（範囲指定・5000 FPS出力を含む）（手動点IDの維持、開始フレーム指定、スナップ、縮小画像からの座標復元、AVI→MP4のフレーム保持など）。GUIについては使用環境のStreamlit画面での操作確認が必要です。

## v7: Edge Counter（エッジ解析）

従来のTkinter版 Edge Counter（2026年7月・v26までの確定要件）をもとにした**再実装**です。
古いアプリの原本ソースは今回の作業時点で未取得のため、画面構成・処理結果の完全互換を保証するものではありません。

1. 新しい「エッジ解析（Edge Counter）」タブから、静止画（PNG/JPEG/BMP/TIFF/WebP）、ローカルの画像ファイル、または読み込んだ動画の1フレームを選びます。動画フレームは元ファイルからOpenCVで読み取ります。
2. `α`,`β`で輝度補正し、必要な場合だけガウシアン/メディアンぼかしを掛けます（初期値OFF）。
3. 輪郭入力を`Binary`（しきい値・反転）または`Canny`（上下しきい値）から選択します。
4. 任意で`Open / Close / Dilate / Erode`のmorphologyを適用します。
5. `cv2.findContours`で輪郭抽出し、面積下限・面積上限のフィルタと `All / Max / Top N` で対象輪郭を選択します。
6. 選ばれた輪郭を1pxのマスクに描画した**後で**、ROI外側とROI・画像端の指定画素をゼロ化します。これにより、ROIの切り抜きに由来する人工的な境界線を作らない処理順としています。
7. 輪郭重畳PNG、輪郭マスクPNG、輪郭統計CSV、輪郭点列CSV、解析条件JSONを保存します。

初期設定は `blur_mode=OFF`, `contour_points=None`, `draw_largest_bbox=False`、対象輪郭は `All` です。`Open Edge Lines` と重い細線化は旧版で削除されたため、実装していません。点列モードには `None / Edge Pixels / Left Envelope / Right Envelope` を用意しています。

CSVは UTF-8 BOM付きです。輪郭統計の`area_px2`は `cv2.contourArea` による閉曲線の幾何学的面積です。輪郭マスクに残った画素数は `visible_edge_pixels` で表します。画像の左上が原点、Xは右向き、Yは下向きです。

**計測時の注意**：ROIを設定しても輪郭選択・面積は元画像で抽出した輪郭に基づきます（輪郭マスク化後にROIを適用）。Cannyの開いた輪郭などでは `contourArea` がゼロや予想外の値になることがあります。点列出力・輪郭画像は画素単位で、サブピクセル計測ではありません。動画の全フレーム一括解析は未対応です。

コードは `videolab/edge_counter.py`（Streamlit非依存のOpenCV解析エンジン）と `videolab/edge_ui.py`（UI）に分割し、`tests/test_edge_counter.py` で回帰テストしています。
